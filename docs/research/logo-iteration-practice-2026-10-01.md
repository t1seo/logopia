# 로고를 고치는 과정: 탐색·비평·정밀화 루프 연구

조사일: 2026-10-01. Figma, Adobe, Google, Pentagram의 1차 자료를 읽었습니다. 이 문서는 로고의 정의보다 **실패를 발견한 뒤 무엇을 바꿀지 결정하는 반복 과정**에 집중합니다. Figma 파일이나 MCP를 실제로 실행한 기록은 아닙니다. 아래 하네스는 출처의 절차를 Logopia에 맞게 재구성한 제안이며, 이미 입증된 생성 품질 개선으로 표현하지 않습니다.

## 결론

생성 → 세 후보 전시 → 가장 덜 나쁜 후보 추천만으로는 반복 디자인이 되지 않습니다. **넓게 탐색하는 단계와 선택한 형태를 다듬는 단계를 분리하고, 실제 그림에서 관찰한 결함을 다음 행동으로 연결해야 합니다.** 모든 후보가 약하면 선택하지 않는 상태가 정상적으로 존재해야 합니다. 긴 프롬프트, 이미지 수, 자동 검사 통과율은 디자인 성과가 아닙니다.

## 제안: 서로 다른 두 개의 반복 과정

아래는 Logopia의 설계 제안입니다. Figma나 Adobe가 특정 상태 머신, 후보 수, 합격 수치를 규정했다는 뜻이 아닙니다.

### A. 탐색: 아이디어가 약할 때 다른 해법을 만듭니다

1. **기준을 고정합니다.** 브랜드의 역할, 주요 사용처, 유지할 자산, 바꿔도 되는 범위, 요청 형식, 피해야 할 인상을 기록합니다. 사용자에게 이미 받은 정보는 다시 묻지 않고 기존 브랜드 자료에서 조사합니다. 사실과 가정은 분리합니다.
2. **방향을 다르게 설계합니다.** 이름만 다른 같은 기호 세 개를 만들지 않습니다. 실루엣, 구조, 비례, 채움과 빈 공간, 리듬 중 무엇이 달라지는지 적습니다. 요청이 심볼이면 모두 심볼이며 워드마크로 범위를 넓히지 않습니다.
3. **작은 탐색 묶음을 만듭니다.** 후보 수와 허용 호출은 사용자의 범위와 비용을 반영해 먼저 정합니다. 개수는 품질 기준이 아닙니다. 이미지 생성 도구가 거친 스케치를 잘 제공하지 못하면 첫 결과를 완성품처럼 포장하지 않고 탐색용이라고 표시합니다.
4. **설명 없이 먼저 봅니다.** 후보 식별자, 브리프, 실제 이미지로 첫 인상과 형태를 관찰합니다. 그 뒤 의도와 일치하는지 비교합니다. 설명을 읽고 나서야 발견되는 숨은 의미를 가시적 장점으로 기록하지 않습니다.
5. **선별 또는 재설정합니다.** 발전시킬 근거가 있는 후보만 정밀화로 이동합니다. 전부 약하면 공통 실패를 기록하고 콘셉트·참조·구조 제약 중 원인 가설과 관련된 항목을 바꿉니다. 같은 지시문의 장식 형용사만 늘리는 재생성을 피합니다.

### B. 정밀화: 살아 있는 아이디어의 결함을 줄입니다

1. **정확한 부모를 고정합니다.** 세션·아티팩트·리비전·원본 해시·사용 크기·팔레트·기존 글자 자산을 기록합니다. 가장 최근 파일이 자동으로 부모가 되지 않습니다.
2. **한 번의 수정 목표를 작게 만듭니다.** 예: 오른쪽 접합부의 답답한 빈 공간을 넓히되, 바깥 윤곽·전체 기울기·색·나머지 간격을 유지합니다. “더 고급스럽게”는 수정 요청이 되지 않습니다.
3. **부모에 연결된 수정을 실행합니다.** 실제 부모 이미지를 편집 도구에 전달합니다. 참조 없이 새 이미지를 만든 경우 독립 후보로 기록하고 정밀 수정 성공으로 표시하지 않습니다.
4. **같은 조건에서 부모와 자식을 비교합니다.** 목표 결함이 줄었는지, 보존 대상이 유지되었는지, 새로운 결함이 생겼는지 각각 확인합니다. 전체 취향 한 줄이나 합계 점수로 상쇄하지 않습니다.
5. **채택·되돌림·방법 전환을 결정합니다.** 자식이 악화됐거나 변화가 불분명하면 부모를 보존합니다. 같은 광학 결함을 이미지 편집으로 제어하지 못하면 편집 가능한 벡터 제작 등 다른 제작 경로를 검토합니다. 그 경로가 없으면 한계를 기록하고 납품 가능하다고 선언하지 않습니다.

두 과정은 오갈 수 있습니다. 다만 이동 이유가 있어야 합니다. 이미 형태가 적합한데 곡선 하나가 어색한 경우는 정밀화, 브랜드와 맞지 않는 상징을 매끈하게 다듬고 있는 경우는 재탐색입니다.

## 관찰을 다음 행동으로 바꾸는 표

아래 표는 제안하는 비평 계약입니다. `관찰`은 실제 파일·영역·표시 조건을 가리켜야 하고, `해석`은 그 관찰이 브리프에 주는 영향을 말해야 합니다. 검토하지 않은 항목은 `미확인`으로 남깁니다.

| 발견 | 기록할 증거 | 다음 행동 | 잘못된 대응 |
|---|---|---|---|
| 후보가 다른 이름의 아무 회사에도 그대로 맞아 보임 | 실제 윤곽의 특징과 비교한 인접 업종 사례. 조사 범위 안의 유사성만 기록 | 구조·비례 등 차별화할 변수를 다시 설계하고 탐색 | 추상적 철학 문장을 덧붙여 독창적이라고 주장 |
| 기술 조건은 맞지만 전부 약함 | 후보별 장점 부족 및 공통 실패, 이번 비교에 쓴 고정 브리프 | `none` 선별 결과와 재탐색 이유를 남김 | 가장 덜 나쁜 안을 자동 우승·추천 |
| 복잡한 이니셜·은유 합성 때문에 무엇인지 불명확함 | 첫눈에 보이는 덩어리, 충돌하는 읽힘, 필요 이상의 작은 요소 | 하나의 구조적 아이디어를 선택하거나 실루엣을 재설계 | 모든 의미를 추가 설명하거나 작게 숨김 |
| 작은 크기에서 틈이 닫힘 | 해당 틈의 위치, 실제 표시 크기, 렌더된 증거 | 그 틈과 연결 부위를 국소 수정 후 같은 크기에서 재검토 | 100% 원본이 선명하므로 작게도 통과 처리 |
| 좌우가 수치상 같지만 한쪽이 무겁게 보임 | 곡률·곡선/직선 접점·색 면적·빈 공간의 관계 | 무게·위치·곡률을 광학적으로 조정 | 중앙 정렬 좌표만 합격 근거로 사용 |
| 수정에서 더 중요한 특징이 사라짐 | 부모/자식의 같은 구역과 보존 조건 비교 | 자식 채택을 거절하고 부모 유지; 수정 범위를 다시 좁힘 | 새 이미지가 더 예쁘다는 이유로 브랜드 단절 무시 |
| 요청하지 않은 컬러·재질이 반복됨 | 프롬프트의 실제 제약과 원본의 관찰 차이 | 제약 충돌·도구 동작 확인, 제한된 교정 후 경로 재판단 | 더 많은 금지어를 무한히 누적 |
| 색이나 표현이 정체성의 일부임 | 해당 브리프와 실제 인접 색/표면 관계 | 지정된 표현을 유지한 채 구조와 재현성을 검토 | 모든 로고를 흑백·기하·미니멀로 통일 |
| 이미 확정한 폰트가 재생성됨 | 사용자가 확정한 자산 및 현재 산출물의 요청 범위 | 심볼만 다시 제작; 조합이 필요하면 실제 확정 자산을 별도로 사용 | 비슷해 보이는 AI 글자를 같은 폰트라고 부름 |
| PNG의 기술 검사는 통과했으나 디자인이 약함 | 크기·알파·색 정보와 별개의 시각 비평 | 기술 합격과 디자인 판단을 별도 보관 | 테스트 수를 디자인 품질의 증거로 제시 |

“일반적으로 보인다”는 말만으로 폐기하지는 않습니다. 비교 범위와 실제 차별점의 부족을 적고, 단순한 도형을 원했다면 그 조건을 존중합니다. 반대로 복잡함이나 숨은 상징의 개수를 독창성으로 보상하지 않습니다. 법적 상표 조사와 기억성 검증은 이 비평으로 완료되지 않습니다.

## 하네스가 보관하고 검사할 최소 정보

- **브리프 스냅샷:** 출처가 있는 사실, 명시적 제약, 가정, 고정 자산, 요구 사용처. 변경했다면 이전 값과 이유를 보존합니다.
- **탐색 기록:** 방향 ID, 구조적 차이, 위험 가설, 호출 예산, 실제 호출과 결과. 여러 제목을 붙인 하나의 구조를 다양한 탐색으로 집계하지 않습니다.
- **원본 연결:** 세션·리비전·아티팩트·원본 해시·부모 ID·정확한 최종 프롬프트. 각 호출은 반환·실패·상태 불명으로 구분합니다. 상태 불명 호출을 몰래 재호출하지 않습니다.
- **증거 연결:** 실제 검사한 이미지/페이지/스크린샷, 표시 크기·배경·크롭 여부, 관찰자 또는 검토 방법. 설정만 있는 CSS 미리보기는 화면 검토 증거가 아닙니다.
- **비평:** 관찰 → 브리프 영향 → 보존할 점 → 바꿀 점 → 다음 행동. 확인 불가·의견 충돌·미해결 항목을 표현할 수 있어야 합니다.
- **결정:** 재탐색, 정밀화, 자식 유지, 자식 거절, 후보 없음, 전달 준비, 미해결 종료. 추천은 선호이고 사용자 승인·납품 검증과 별개입니다.
- **변경 검증:** 목표 결함의 개선, 보존 조건의 회귀, 새로운 결함을 별개로 판정합니다. 자동 검사에 좋은 결과와 시각적으로 좋은 결과를 하나의 합계로 만들지 않습니다.

하네스는 이 정보가 빠졌거나 서로 다른 파일을 가리키는 경우를 잡을 수 있습니다. **브랜드에 어울림, 고유한 인상, 우아한 곡선 같은 미적 판단을 해시나 스키마 검사로 자동 보증할 수는 없습니다.** 숫자 점수의 임계치 대신 근거가 있는 선택 사유와 반례를 남기는 것이 이 제안의 목적입니다.

## 중단과 방향 전환

무한 루프를 방지하려면 탐색·수정 호출 예산을 시작할 때 정하고 실제 호출만 차감합니다. 예산 값은 작업 범위의 운영 선택이며 좋은 로고를 보장하는 숫자가 아닙니다.

- 모든 후보가 핵심 요구를 놓치면 같은 후보군 안에서 선정을 강제하지 않습니다. 공통 원인을 가설로 남겨 브리프 또는 구조적 방향을 바꿉니다.
- 같은 결함을 고치려는 제한된 시도에서 개선 증거가 없으면 같은 방식의 추가 호출을 정당화하지 않습니다. 문제가 콘셉트인지, 프롬프트 충돌인지, 편집 제어인지 구분하고 방법을 바꿉니다.
- 비평에 실제 그림을 본 증거가 없으면 시각 합격을 기록하지 않습니다. 도구 제한은 미확인 상태로 남깁니다.
- 예산이 끝났다는 이유로 후보를 완료품으로 승격하지 않습니다. 가장 나은 부모와 미해결 항목, 다음에 필요한 행동을 전달합니다.
- 사용자 승인 없이 이미 확정된 폰트나 공식 로고 자산을 갈아끼우지 않습니다. 탐색을 계속할 권한과 공식 브랜드 채택 권한은 다릅니다.

## 이번 업데이트를 검증할 구체적 시나리오

다음은 구현·운영 검증 제안입니다. 아직 실행 결과가 아닙니다.

1. **모두 약한 후보:** 기술 검사를 통과한 세 후보에 핵심 적합성 문제가 남아 있을 때 `none`을 보존하고 자동 추천하지 않아야 합니다.
2. **누락된 시각 증거:** 프롬프트·설명·HTML 크기 설정만으로 작은 크기 판정을 완료할 수 없어야 합니다.
3. **국소 수정의 회귀:** 틈은 개선됐지만 바깥 윤곽이 바뀐 자식을 보존 조건 실패로 기록하고 부모를 되살릴 수 있어야 합니다.
4. **독립 재생성:** 실제 부모 참조 없는 생성은 기존 후보의 검증된 수정으로 기록되지 않아야 합니다.
5. **범위 보존:** 확정 폰트·심볼만 요청한 브리프에서 워드마크·폰트 탐색으로 이탈하지 않아야 합니다.
6. **예산 소진:** 생성 횟수가 끝나도 디자인 합격·사용자 승인·실사용 준비가 자동으로 참이 되지 않아야 합니다.
7. **표현 다양성:** 컬러가 중요한 캐릭터·게임용 브리프를 일반 심볼용 흑백 규칙으로 실패 처리하지 않아야 합니다.
8. **실제 결과 비교:** 이전/새 과정의 원본, 프롬프트, 호출 수와 모델 불명 사항을 보존하고 같은 브리프·조건에서 선입견을 줄인 검토를 합니다. 개선과 미개선이 함께 드러나야 하며, 작은 표본으로 스킬의 일반적 우월성을 주장하지 않습니다.

## 원인 진단의 한계

이 자료는 “AI가 원래 로고를 못 만든다”는 결론을 증명하지 않습니다. Figma의 AI 비평 기능 소개도 독립적인 로고 품질 벤치마크가 아닙니다. 이 문서가 지지하는 것은 제작 과정의 구조입니다.

현재 실패를 원인별로 구분하려면 **실제 후보와 프롬프트, 무엇을 보존/변경하려 했는지, 어떤 관찰로 다음 안을 만들었는지**를 함께 비교해야 합니다. 모델의 제어 한계, 방향 설계의 부족, 업데이트가 만든 제약 충돌은 동시에 있을 수 있습니다. 이번 하네스의 성과는 이 원인을 분리할 기록과 분기점이 생기는지부터 검증해야 합니다.

### 실무 페르소나의 공통 지시문

다음 문구는 Logopia가 합성한 역할 계약입니다. 실제 디자이너의 발언 인용이 아닙니다.

> 당신은 관찰과 제작을 반복하는 브랜드 아이덴티티 디자이너입니다. 회사가 실제로 하는 일, 기존 자산, 사용 환경에서 출발하십시오. 이미지가 나오기 전에 무엇이 좋아야 하는지 정하고, 나온 뒤에는 그 기준에 맞춰 그림을 보십시오. 의미를 모두 담으려 하지 말고 식별에 기여하는 구조를 선택하십시오. 익숙한 모티프는 그 자체로 금지하지도, 설명만으로 정당화하지도 마십시오. 근거가 있는 장점과 눈에 보이는 결함을 함께 말하십시오. 좋은 부모를 보존하며 국소적으로 개선하고, 아이디어가 약하면 미련 없이 방향을 다시 잡으십시오. 후보가 모두 약할 수 있습니다. 유명인의 이름, 그럴듯한 이야기, 미적 점수로 결과를 과장하지 마십시오.

이 페르소나는 한 번의 생성 프롬프트에 긴 인물 소개로 붙이지 않습니다. 조사·방향 설계·검토·수정의 각 단계에서 아래 짧은 역할 계약을 실행합니다. 특정 디자이너의 작품명이나 명성을 이미지 프롬프트에 넣는 것으로 대체하지 않습니다.

### 페르소나가 실제 루프에 기여했는지 확인하는 방법

역할 이름을 기록하는 데서 끝내지 않습니다. 하네스에 **브리프에서 정한 제약 → 실제 후보의 관찰 → 선택/재탐색 이유 → 수정할 관계 → 수정 전후의 변화**가 이어져야 합니다. 각 단계의 기록은 필요한 결정만 짧게 남기고, 다음 이미지로 확인하지 않은 긴 해설을 성과로 집계하지 않습니다.

Hail Mary의 이번 요청에 적용하면 확정 서체는 고정하고 심볼만 제작합니다. 공식 브랜드 자료의 성격과 실제 제품군을 조사하되, 기존 달·별을 반드시 유지하거나 무조건 버린다는 결론을 미리 내리지 않습니다. 먼저 구조가 다른 소수의 방향을 만들고 설명을 가린 검토로 선별한 뒤, 발전시킬 근거가 있는 부모 하나의 조형 결함을 실제 편집으로 줄입니다. 모두 약하면 어떤 구조적 가정을 바꾸어 새 탐색을 했는지 남깁니다. 새 후보를 만들지 않고 페르소나 문서만 추가한 상태를 이 요청의 완료로 표현해서는 안 됩니다.
