# SEAM 실제 생성 비교

2026-09-19, 가상의 개인 글쓰기 앱 SEAM입니다. [공통 Brief](brief.json)는 글 조각을 짧은 초고로 모으는 용도, 차분하고 자신감 있는 인상, Ink/Coral/Paper 색 역할, 문자·별·Sparkle·무한대·캐릭터 제외 조건을 공유합니다.

먼저 [블라인드 비교 화면](blind/index.html)을 보세요. 방법이나 생성자의 판단은 표시하지 않습니다. A/B는 **화면의 위치 표기**이며 아래 Baseline/Improved 방법과 고정 대응하지 않습니다. 네 가지 결과와 구체적인 근거를 입력하여 JSON을 내려받을 수 있습니다. 아직 사용자 응답은 저장하지 않았습니다.

## 비교 조건

- Baseline 3개: 변경 전 `d7d3cd4`의 실제 Builder로 만든 프롬프트입니다. [Builder 원문](../baseline/app_icon_prompts.py.txt), `baseline-1/2/3.json`과 `prompts/baseline-*.txt`를 보존했습니다. 기존 방식을 일부러 나쁘게 재작성하지 않았습니다.
- Improved 3개: 동일한 제품·팔레트·세 방향 유형(pictogram, abstract, soft_3d)에 구체적인 비례·틈·곡률·재질·실패 위험과 선택한 Reference 특성을 더했습니다. `improved-1/2/3.json`에 설계 의도와 실제 입력 계획을 저장했습니다.
- 동일한 노출 도구 `image_gen__imagegen`, 각 방법 3회, 총 **6회 생성·0회 수정**입니다. 최대 12회의 남은 6회를 품질이 좋아 보일 때까지 재추첨하는 데 쓰지 않았습니다. 별도 9개 탐색을 생성하지 않았습니다.
- 양쪽 모두 Prompt로 1536×1536을 요청했고 실제 반환은 모두 **1254×1254**입니다. 노출된 도구에는 size/seed/model 인자가 없습니다. 원본을 변환하지 않았습니다. 실제 모델·seed·샘플링 설정은 **unreported**이므로 동일 모델을 검증한 통제 실험이라고 말할 수 없습니다.
- Improved 1/2는 Craft 이미지에서 확인한 곡률·간격의 **분석 텍스트만** 전달했습니다. Improved 3은 직접 열어본 저장소의 기존 생성 이미지 `soft-3d-quality-v1.png`를 **실제 `referenced_image_paths`로 전달**했습니다. 잎·하트 윤곽, 녹색과 잔점 질감은 가져오지 않도록 구분했습니다. 외부 제품 원본은 생성 Provider에 첨부하지 않았습니다.
- 개선 호출은 `prompt_result.input_plan.arguments`를 그대로 실제 도구에 넘겼습니다. `calls.json`은 반환 경로, 원본/Prompt 해시, 실제 도구 인자 종류와 치수를 기록합니다. 원래 도구 반환 파일과 저장소 원본 6개가 해시로 일치합니다.
- 비교 Gallery는 동일한 주변 배경·크기·Mask를 쓰며 3쌍의 좌우를 seed로 균형 배치했습니다. Method 파일명·프롬프트·자체 rationale은 화면에서 숨겼습니다. Organizer Manifest는 접근 제어가 아니므로 응답 전에 제공하지 않는 것이 좋습니다.

## 실제 관찰 — AI의 관찰이며 사용자 선호가 아닙니다

| 쌍 | Baseline에서 보이는 것 | Improved에서 보이는 것 | 남은 위험 |
| --- | --- | --- | --- |
| 1 / note | 외곽선 문서, 오른쪽 위 접힘, 내부 가로줄 3개입니다. 32px에서 가로줄이 짧은 획으로 남습니다. | 채워진 몸통과 산호색 모서리 하나로 줄었습니다. 모서리와 몸통 사이 밝은 L형 틈이 32px에서도 보입니다. | 여전히 일반적인 파일 아이콘과 가까울 수 있습니다. 내부 획을 없앤 것이 곧 브랜드 고유성의 증거는 아닙니다. |
| 2 / joined fragments | 두 굵은 곡선이 중앙에서 서로 감깁니다. 중앙 흰 틈은 좁고 윤곽은 S처럼 이어집니다. | 잉크색 상단·오른쪽 띠와 산호색 아래·안쪽 띠가 열린 직각 채널을 만듭니다. 32px에서도 두 방향과 틈이 남습니다. | 큰 원본에서 상단 띠와 오른쪽 띠의 시각적 무게가 다릅니다. 덜 감긴 형태를 선호할지는 미검증입니다. |
| 3 / tactile fold | 잉크색 양면과 가운데 세로 접힘이 보이며, 요구한 산호색 식별 부분은 보이지 않습니다. 32px에서는 작은 어두운 직사각형에 가깝습니다. | 오른쪽 위 산호색 말린 끝과 비대칭 외곽이 생겼고, 32px에서도 산호색 끝이 남습니다. | 매끈한 재질 요청에도 잔점 질감이 남았고 조명 표현이 더 강합니다. Reference의 질감 전이인지 실행 변동인지 이 표본으로 구분할 수 없습니다. |

세 결과 모두 별개의 형식적 선택이 보이지만 선호의 승자를 자동 저장하지 않았습니다. 작은 크기 검사는 공식 플랫폼 필수 출력 규격이 아닙니다. 색상 HEX의 픽셀 일치, QA 통과, 사용자 승인, 상표 검증, 플랫폼 적합성을 이 표로 대신하지 않습니다.

## 해석 범위와 보존

여러 지침·제품 맥락·Reference 전달을 함께 바꾼 **묶음 비교**입니다. 어떤 요소 하나의 인과 효과나 시장 성과를 입증하지 않습니다. 한 Brief·방법당 3개·미공개 모델·실행 간 변동성이라는 한계가 있습니다. 두 번째 Brief나 정교화 호출은 추가로 실행하지 않았습니다.

로컬 Helper Session은 `seam-craft-2026`, 최종 revision 8, 후보 `a1,a2,a3,b1,b2,b3`입니다. Baseline 원본 3개를 등록하고 Reference 2개를 추가한 revision 5에서 개선 Prompt를 만들었습니다. 이후 원본 등록은 같은 조건의 카탈로그 추가이며 별도 생성이 아닙니다. `blind-selection.json`은 최종 revision 8을 명시합니다. 블라인드 화면·일반 Gallery·원본 총 18개 PNG의 브라우저 전후 해시가 같습니다.

새 clone에는 로컬 Session과 Reference 캐시가 없지만 이 폴더의 HTML·PNG·Prompt는 그대로 열립니다. 재생성은 새로운 이미지 호출이므로 같은 픽셀을 보장하지 않습니다. 같은 원본을 재비교하려면 새 Session에 각 JSON의 `app_icon`과 실제 PNG/Prompt를 `import`한 뒤 현재 revision으로 선택 파일을 만드세요. 기존 Session의 revision을 임의로 바꾸거나 원본을 덮어쓰지 마세요.
