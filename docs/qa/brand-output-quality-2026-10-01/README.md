# 브랜드 로고 출력 품질 실험 · 2026-10-01

기존 Logopia와 개선 워크플로에 같은 제품 브리프를 적용하여 결과와 생성 근거를 남기는 실험입니다. 사용자가 지적하신 불필요한 베이지색 배경, 인위적인 산업·게임 회사 이미지와 시네마틱 표현, 제품에 맞지 않는 형태, 조화롭지 않은 색상 조합을 검토합니다.

[원본 비교 페이지](index.html)에는 실제 생성된 기존·개선 워크플로의 원본 총 6개를 브리프별로 나란히 표시합니다. ‘개선 워크플로’는 변경한 방법의 이름이며, 결과 품질이 더 높다는 판정은 아닙니다. 사용자 선호 결과는 수집되지 않았습니다. 이 자료는 미적 승자나 일반적인 품질 향상을 결론 내리는 보고서가 아닙니다.

## 고정한 실험 조건

- 브리프는 TIDE 추상 심볼, 모아 한글 워드마크, Folio 심볼·영문 이름 조합의 3개입니다.
- 각 브리프에 기존·개선 워크플로별 1회씩, **이미지 생성 총 6회**를 배정했습니다. 편집과 재시도 예산은 각각 0회입니다.
- 실제 생성 6회가 완료됐으며, 실패·편집·재시도는 모두 0회입니다. 실행 근거는 [호출 기록](calls.json)을 확인해 주세요.
- 원문 요청, 브랜드명과 정확한 글자, 산업·대상, 로고 유형·사용처, 공통 형태 방향, 배경 요구, 금지 요소를 공유합니다.
- 콘셉트 구체화, 역할과 근거가 있는 팔레트, 헬퍼가 만든 프롬프트, 개선 워크플로가 지원하는 추가 맥락은 각 방법의 일부입니다.
- 참조 이미지나 이전 후보를 첨부하지 않습니다. 도구에 모델·시드·샘플링 설정 제어가 노출되지 않아 이를 고정했다고 주장하지 않습니다.
- 시각적으로 약한 후보도 교체하지 않습니다. 실제 실패와 호출 상태는 [호출 기록](calls.json)에 남깁니다.

세부 조건과 비교 항목은 [protocol.json](protocol.json)을 확인해 주세요. 프로토콜의 생성 상태와 개선 입력 준비 기록의 상태 문구는 각각 작성 시점의 기록이며, 실제 이미지 호출 상태는 `calls.json`을 따릅니다.

## 공통 브리프와 보존 원본

| 브리프 | 배경 요구 | 기존 원본 | 개선 원본 | 원본 크기, 두 방법 동일 |
|---|---|---|---|---|
| [TIDE](briefs/tide.json) | 불투명 순백색 | [PNG](originals/baseline-tide.png) | [PNG](originals/improved-tide.png) | 1254 × 1254px, 1:1 |
| [모아](briefs/moa.json) | 불투명 순백색 | [PNG](originals/baseline-moa.png) | [PNG](originals/improved-moa.png) | 1774 × 887px, 2:1 |
| [Folio](briefs/folio.json) | 불투명, 색 미지정 | [PNG](originals/baseline-folio.png) | [PNG](originals/improved-folio.png) | 1665 × 945px, 37:21 |

`originals/`에는 실제 도구가 반환한 PNG 원본을 보존합니다. 보기 페이지는 두 방법에 동일한 프레임과 `object-fit: contain`을 적용하여 원본 전체를 표시하며, 이미지를 자르거나 배경을 바꾸지 않습니다. 넓은 화면에서는 좌우, 좁은 화면에서는 위아래로 배치하도록 설정했습니다. 작게 보기도 원본 파일을 CSS 표시 크기만 바꾸어 재사용합니다.

작게 보기의 폭은 TIDE 32·48·64·128px, 모아 96·144·240px, Folio 180·240·360px입니다. 이는 **여백을 포함한 전체 캔버스 폭**이며, 로고 자체의 외곽을 추출한 실사용 크기 측정을 뜻하지 않습니다. 원본의 비율과 여백이 달라 같은 프레임에서도 로고의 실제 점유 면적은 다릅니다.

Folio는 배경색을 지정하지 않았습니다. 기존 가이드에 근거한 종이색 배경 선택 자체를 배경 요구 위반으로 평가하지 않습니다.

## 입력·출처와 기술 측정

- [기존 워크플로 안내](baseline/README.md): 입력 작성, 프롬프트 생성, import 및 재현 방법입니다.
- [출처·버전 기록](baseline/provenance.json): 기존 Git HEAD `4d102c260ec1b65e086ab5f5699cee4ffcbdad01`, 패키지 `0.8.0`, 의존성·도구 버전을 기록했습니다.
- [입력 해시](baseline/input-sha256.txt)와 [보존 소스 해시](baseline/source/SHA256SUMS): 입력·프롬프트와 기존 소스 스냅샷의 추적 근거입니다.
- 기존 실제 프롬프트: [TIDE](baseline/prompts/tide.txt), [모아](baseline/prompts/moa.txt), [Folio](baseline/prompts/folio.txt).
- 개선 실제 프롬프트: [TIDE](improved/tide/prompt.txt), [모아](improved/moa/prompt.txt), [Folio](improved/folio/prompt.txt).
- [개선 입력 준비 기록](improved/execution-manifest.json)과 [개선 소스 해시](improved/provenance/source-hashes.json): 구조화 브리프·디자인 입력·팔레트·최종 프롬프트와 실행 소스의 추적 근거입니다. 각 브리프의 상세 입력은 비교 페이지에서 연결합니다.
- 보존 원본 해시: [기존](baseline/original-sha256.txt), [개선](improved/original-sha256.txt).
- [호출 기록](calls.json): 호출별 원본 도구 경로, 보존 파일, 사용 프롬프트, 노출된 매개변수와 실제 실행 상태입니다.
- 기술 측정 보고서: [기존 원본](baseline/observed-technical.json), [개선 원본](improved/observed-technical.json). 보존 원본에서 관찰한 파일·픽셀 속성의 기록입니다. 미적 완성도, 브랜드 적합성, 정확한 글자 또는 사용자 선호를 자동으로 판정한 자료가 아닙니다.

## 해석 범위

생성 방식과 프롬프트를 보지 않은 별도 AI 검토자가 원본 6개를 확인했습니다. [블라인드 관찰 기록](blind-observations.md)과 [평가 후 공개한 A/B 매핑](blind-mapping.json)을 보존합니다. 검토자는 TIDE·Folio의 변경 후 시안을 선호했고, 모아는 변경 후 시안에 근소한 우세를 주었습니다. 이는 사용자 승인이나 납품 가능 판정이 아닙니다.

남은 문제도 있습니다. 모아는 여전히 획이 두껍고 유아용 인상이 남으며, TIDE는 물결처럼 해석될 여지가 있습니다. Folio는 이름의 비중이 커졌지만 심볼 비례와 실제 헤더 크기의 검토가 필요합니다. 영화·게임식 입체 연출 문제는 이번 기존·개선 표본 모두에서 뚜렷하게 재현되지 않았으므로, 해당 문제가 해결됐다는 비교 증거로 사용하지 않습니다.

방법·브리프마다 표본이 1개이므로 통계적인 품질 향상을 판단할 수 없습니다. 기술 측정, 시각 검토, 사용자 선호는 서로 다른 증거로 구분해야 합니다. 현재 사용자 선호 결과는 수집되지 않았습니다. 이 제한된 비교를 모든 요청의 품질 향상이나 상용 적용 준비 완료로 일반화하지 않습니다.

공식 Codex Computer Use를 사용할 수 없어 **비교 HTML의 실제 브라우저 렌더링과 CSS 표시 크기는 검증하지 못했습니다.** 파일·로컬 링크·원본 해상도에 대한 정적 검사를 화면 검증으로 해석하지 않아야 합니다. 표기된 작게 보기 크기는 HTML·CSS 설정값이며, 화면 폭에 따라 더 작게 표시될 수 있습니다.
